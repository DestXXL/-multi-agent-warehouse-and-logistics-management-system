# Конструктор склада: формат и демонстрация

Запуск приложения описан в [DEVELOPMENT.md](DEVELOPMENT.md).

Откройте [конструктор](http://127.0.0.1:5173/?view=layout). Он получает серверную геометрию в локальную копию редактора. Клики, изменение размера и загрузка JSON сами по себе не меняют симуляцию.

## Воспроизводимый показ

Начальные условия: свежий backend со встроенной картой, две стоянки и нулевой такт. Для уже изменённой сессии перезапуск удалит её данные; перед показом сохраните нужный макет через «Скачать JSON».

1. Измените ширину с 12 на 14. Выберите «Стеллаж», задайте 4 яруса и поставьте его в (12, 3).
2. Выберите «Стоянка» и добавьте её в (0, 4). Нажмите «Проверить» – ожидается сообщение о корректности.
3. Для отрицательного примера добавьте стены в (0, 3), (1, 4), (0, 5). Новая стоянка окажется изолированной; проверка должна сообщить о несвязности рабочих точек.
4. Удалите эти стены инструментом «Ластик / проход» и повторите проверку.
5. Скачайте JSON, измените одну клетку и загрузите сохранённый файл. Геометрия восстановится в редакторе, сервер ещё не изменится.
6. Нажмите «Применить к симуляции». Это удалит прежние заказы и создаст новую смену с техникой из макета; остатки на сохранившихся адресах переносятся.
7. Нажмите **«Добавить демозаказ на склад» в конструкторе**, затем перейдите в диспетчерскую и запустите симуляцию. Кнопка создаёт заказ между первыми точками забора и отгрузки применённого склада; изменения, оставшиеся только в редакторе, она не использует.
8. Откройте планшет назначенного погрузчика, примите задание, подтвердите забор и доставку после прибытия. Дождитесь возвращения на стоянку.
9. Попытка применить макет после начала смены, в том числе на паузе, должна получить HTTP 409. Для новой смены нужен явный сброс.

Ожидаемые результаты – критерии показа, а не обещание успешного движения на любом допустимом макете. Динамические взаимные блокировки возможны.

## JSON версии 1

Небольшой корректный пример:

```json
{
  "version": 1,
  "width": 4,
  "height": 4,
  "cells": [
    {"x": 0, "y": 0, "kind": "robot", "levels": 1},
    {"x": 1, "y": 0, "kind": "pickup", "levels": 1},
    {"x": 3, "y": 3, "kind": "shipping", "levels": 1},
    {"x": 2, "y": 2, "kind": "rack", "id": "A-0103", "rack_type": "pallet_high", "width_mm": 2700, "depth_mm": 1100, "height_mm": 6000, "levels": 4, "positions_per_level": 2}
  ]
}
```

| Поле | Ограничение |
| --- | --- |
| `version` | 1; при отсутствии сервер подставляет 1 |
| `width`, `height` | Целые числа 4–40 и 4–30 |
| `cells` | Не более 1200 объектов, без повторяющихся координат |
| `x`, `y` | Целые неотрицательные координаты внутри карты |
| `kind` | `rack`, `wall`, `pickup`, `shipping`, `robot` |
| `id` | Стабильный уникальный адресный префикс стеллажа; по умолчанию строится из координат |
| `rack_type` | `pallet_high`, `pallet_standard`, `medium_shelving`, `small_parts_shelving`; каталог и значения по умолчанию доступны через `GET /api/rack-types` |
| `width_mm`, `depth_mm`, `height_mm` | Положительные индивидуальные размеры стеллажа в миллиметрах; по умолчанию берутся из его типа |
| `levels` | Целое 1–12 для стеллажа; по умолчанию берётся из типа |
| `positions_per_level` | Целое 1–100; число адресуемых мест на ярусе; по умолчанию берётся из типа |

Лишние поля запрещены. Нужны хотя бы одна стоянка, точка забора и отгрузка. Все рабочие точки должны соединяться проходами; у каждого стеллажа должна быть хотя бы одна соседняя доступная клетка. Пустые клетки проходимы, стены и стеллажи блокируют движение.

Серверные значения по умолчанию не заменяют полный формат браузерного импорта: для переносимых файлов указывайте `version` и `levels` явно, как в экспорте редактора. Браузер отклоняет файл больше 250000 байт. Это ограничение загрузчика интерфейса, не общий предел HTTP API.

## Проверка, применение и сохранение

| Действие | Результат |
| --- | --- |
| `GET /api/layout` | Текущая серверная геометрия |
| `POST /api/layout/validate` | Проверка без изменения склада; ошибки геометрии возвращаются в `errors` |
| `PUT /api/layout` | Проверка и применение, затем рассылка нового состояния |
| «Скачать JSON» | Экспорт текущей копии редактора, даже если она ещё не проверена |
| «Загрузить JSON» | Разбор и серверная проверка файла, затем замена копии редактора |
| «Сбросить склад» | Сохранение применённой геометрии, удаление прогресса и заказов пользовательской смены |
| Перезапуск backend | Потеря пользовательской геометрии; возврат встроенного склада |

Применение допускается только при остановленной симуляции, нулевом такте и отсутствии непустого прогресса заказов: все имеющиеся заказы должны быть `pending`. Такие ещё не запущенные заказы при применении будут удалены. После запуска паузы недостаточно.

Макет содержит геометрию и параметры стеллажей; позиции хранения, товар, назначения, перекрытия и журнал являются состоянием симуляции. Стены и стеллажи превращаются в общие `obstacles`; каждая ячейка стеллажа и её параметры также передаются в снимке как `racks`. Адреса товара имеют вид `A-01-L03-P02`: стеллаж, ярус и место. Число мест определяется произведением ярусов на мест в ярусе. Размеры каждой адресуемой области вычисляются из стеллажа. Коробки занимают координаты на плоскости яруса без пересечений, с поворотом в горизонтальной плоскости и проверкой высоты. Процент заполнения в интерфейсе считается по занятым адресам, а не по объёму. В редакторе параметры выбранного стеллажа можно менять отдельно; изменение отклоняется, если размещённые коробки перестают помещаться. Вертикальные перемещения и физическая ширина проездов не моделируются.

При уменьшении размера объекты за границами остаются в данных. Удалите их после временного возврата размера либо исправьте JSON и проверьте его. Сервер не обрезает карту автоматически.

## Известные ограничения показа

Диспетчерская рисует клетки по фактическим размерам, но подпись «12 × 8» и текст «2 узла» пока фиксированы. Стены отображаются тем же обозначением, что стеллажи, но без размеров и подсказки. После применения сообщение конструктора предлагает добавить заказ в диспетчерской, хотя отдельной формы там нет; кнопка «Добавить демозаказ на склад» уже находится в конструкторе. Доступен и API.

Статическая связность не гарантирует разъезд погрузчиков. Данные хранятся только в памяти backend-процесса и сбрасываются при его перезапуске. Полный список ограничений: [состояние проекта](docs/project-status.md). Имеющиеся автоматические проверки и их пределы: [DEVELOPMENT.md](DEVELOPMENT.md).
