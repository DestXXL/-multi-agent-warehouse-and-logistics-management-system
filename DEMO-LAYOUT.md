## Запуск на Windows (два терминала, из папки репозитория)

Терминал 1:
```powershell
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r backend/requirements.txt
.venv\Scripts\python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```
Терминал 2 (Node.js с npm):
```powershell
cd frontend
npm ci
npm run dev
```
Открыть http://localhost:5173/?view=layout. Диспетчерская: http://localhost:5173/?view=control. macOS/Linux: `python3` и `.venv/bin/python` вместо Windows-команд.

## Сценарий на 3–5 минут

1. Открыть конструктор: он показывает исходную карту товарища. Изменить ширину с 12 на 14.
2. Выбрать «Стеллаж», установить 4 яруса, разместить в (12, 3). Счётчик мест изменится. Выбрать «Стоянка» и добавить в (0, 4). Показать инструменты забора и отгрузки; оставить исходные точки.
3. Нажать «Проверить». Для отрицательного примера поставить стенами кольцо вокруг новой стоянки: (0,3), (1,4), (0,5). Проверка сообщит, что точки не соединены. Удалить стены ластиком. Проверить снова.
4. Скачать JSON; изменить одну клетку, загрузить скачанный файл — исходный макет вернётся в редактор. Загрузка не меняет работающую симуляцию.
5. «Применить к симуляции» создаёт пустую смену. Нажать «Добавить демозаказ на склад»: заказ создаётся между первой точкой забора и первой отгрузкой именно применённого склада.
6. Перейти в диспетчерскую, нажать «Начать симуляцию», открыть планшет назначенного погрузчика. Принять задание, дождаться прибытия, подтвердить забор и доставку. Это исходный цикл товарища на новой карте.
7. Показать отказ применения макета во время смены, в том числе на паузе. Для нового макета сначала сбросить симуляцию в диспетчерской. Сброс сохраняет применённую геометрию, но очищает задания. Перезапуск сервера возвращает исходный склад — загрузить JSON и применить снова.

## Что объяснить преподавателю

Конструктор реализует подготовку среды и модель карты из периода 1 приложенного `project-plan (2).md`. Менеджер, агент робота и агент зоны сохраняют отдельные роли. Геометрию и допустимость размещения проверяет обычный backend, а не LLM. На этом этапе агенты детерминированные; реальная LLM остаётся дальнейшим этапом плана.

Ярусы — статические метаданные стеллажа (1–12); сумма ярусов — число условных мест, по одному на ярус клетки стеллажа. Вертикальное перемещение груза, адресное хранение по ярусам и физические габариты техники пока не реализованы. Все пустые клетки — проходимые клетки; ширина прохода задаётся оставленным количеством свободных клеток, нормативы безопасности не моделируются. Связность проверяется без динамической занятости техникой; отсутствие взаимных блокировок в произвольном макете не гарантируется.

Статья https://cyberleninka.ru/article/n/mnogoagentnaya-sistema-upravleniya-skladskimi-peremescheniyami указана как тематический источник. Доступ при подготовке закрыт капчей; конкретные алгоритмы или выводы статьи не приписываются реализации. Для точного сопоставления нужен текст статьи. Восстановлен и прочитан приложенный план; старые ответы в чате доступны лишь как ссылки на содержимое.

## Контракт

`GET /api/layout` — текущая статическая геометрия; `POST /api/layout/validate` — проверка без изменения состояния; `PUT /api/layout` — атомарное применение и публикация через существующий WebSocket.

JSON v1: `version`, `width` (4–40), `height` (4–30), `cells`: `x`, `y`, `kind` (`rack`, `wall`, `pickup`, `shipping`, `robot`), `levels` (1–12, только для стеллажа; для остальных 1). Координаты от нуля. Нельзя пересекать объекты, выходить за карту, оставлять недоступными рабочие точки или стеллажи. Нужны хотя бы одна стоянка, забор и отгрузка. Макет сохраняется скачиванием JSON, база данных и автоматическое сохранение на сервере не добавлены.

Стены и стеллажи передаются старым агентам в `obstacles`. Тип и ярусы сохраняются в статическом макете; диспетчерская пока отображает их как препятствия. При применении очищаются заказы/товары и создаются роботы по стоянкам. Допустимо только до запуска заданий: пауза активной смены недостаточна. Применение начального макета также очищает три демонстрационных заказа; кнопка демозаказа создаёт новый.

```powershell
.venv\Scripts\python -m unittest discover -s tests -v
cd frontend
npm run build
```
