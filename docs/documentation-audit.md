# Отчёт о документационном аудите

Разделы 1–6 ниже сохраняют результаты первого прохода от 15 октября 2026 года, включая прежние оценки и проверки. Повторный аудит от 17 октября приведён отдельно в конце; результаты первого прохода не означают повторного запуска тестов.

Дата – 15 октября 2026 года. Репозиторий – [DestXXL/-multi-agent-warehouse-and-logistics-management-system](https://github.com/DestXXL/-multi-agent-warehouse-and-logistics-management-system). Исследован коммит `cf9949b3e549b6556c81f5ebb169a16194a98677`; изменения подготовлены в рабочем дереве `makar`, без коммитов и публикации.

## 1. Что обнаружено

Исследованы все 28 отслеживаемых файлов исходного состояния: семь документов, восемь файлов backend, десять файлов frontend, два тестовых файла и `.gitignore`. Проверены история и удалённые ссылки веток. Вложенных `AGENTS.md`, GitHub-шаблонов, CI и LICENSE в отслеживаемом дереве нет.

Критические для понимания недостатки:

1. Архитектура смешивала централизованные алгоритмы, будущие предложения LLM и физический склад. В коде один общий планировщик маршрутов, а не независимый агент на каждый погрузчик; нет протокола межагентных сообщений.
2. `HANDOFF.md` предлагал начать работу от отсутствующей удалённой ветки. `DEMO-LAYOUT.md` сохранял устаревшую базу PR. Контекст №2 сообщал уже неверное соотношение веток.
3. В описании проверок можно было принять желаемую проверку достижимости до применения за реализованную. Фактически резерв и назначение записываются раньше поиска пути.
4. План содержал сценарии переназначения, компетенций, декомпозиции и LLM рядом с готовыми возможностями без достаточно ясной границы.

Остальные существенные недостатки:

* В README неверно описывался фиксированный адрес backend; реальный адрес использует имя хоста страницы.
* Полный тестовый запуск требовал `requirements-dev.txt`, но инструкции установки были разбросаны и местами не включали его.
* Не были чётко разделены reset пользовательского макета, сброс встроенного сценария и перезапуск процесса.
* Таблица API пропускала водительские действия, перекрытия/открытие проходов и API макетов.
* Пример состояния пропускал часть фактических полей и не был обозначен как сокращённый.
* `project-plan (2).md` упоминался как источник, хотя такого файла в репозитории нет.
* Сведения о пяти тестах и старых проверках выдавались без достаточной привязки к версии.
* Повторялись команды запуска, описание ролей, архитектуры и исторические сведения.
* Не объяснялись пределы тестов, отсутствие метрик эффективности и неполнота автономности.
* Не раскрывались фиксированные подписи пользовательской карты и отсутствие формы заказа в диспетчерской.
* Связь реализации со статьёй описывалась увереннее, чем позволял недоступный полный текст.

## 5. Оставшиеся проблемы

Документация не устраняет ограничения кода. Полный реестр S1–S15 находится в [project-status.md](project-status.md).

Наиболее существенны неполная автономность агентов, отсутствие единого контракта предложений, резервирование до проверки пути, возможные взаимные блокировки и отсутствие метрик эффективности. Сохраняются дефекты подписей/подсказок UI, неполное покрытие тестами, отсутствие CI и закреплённого Python-окружения. Лицензия, детали будущей LLM и календарные сроки требуют решения команды. Персональные обязанности сверх исходного распределения не выводились из имён веток.

Документация готова к проверке в качестве описания прототипа; полнота реализации темы курсовой остаётся отдельным вопросом.

## Повторный аудит – 17 октября 2026 года

### 1. Проверенные рекомендации

[Официальное руководство Codex](https://learn.chatgpt.com/docs/agent-configuration/agents-md) описывает цепочку инструкций при запуске: глобальные правила, затем каталоги от корня проекта до cwd; внутри каталога приоритет имеет `AGENTS.override.md`, затем `AGENTS.md`, затем настроенные fallback-имена. Вложенные подкаталоги ниже cwd не загружаются все сразу. По умолчанию общий предел составляет 32 KiB. Изменение файла не следует считать гарантией обновления инструкций уже работающей сессии.

Обязательное чтение README не является требованием Codex. Ссылка допустима как навигация, но сама по себе не загружает документ и не превращает его в инструкции. Явное «прочитайте README» было локальным требованием нашего прежнего AGENTS и теперь заменено контекстом по необходимости. Важные правила остаются непосредственно в AGENTS.

[AGENTS.md](https://agents.md/) подтверждает свободный Markdown-формат и назначение файла для агента; рекомендуемые 50–100 строк не являются обязательным стандартом. [Репозиторий OpenAI Codex](https://github.com/openai/codex) проверен как официальный проект и точка входа в документацию; аудит реализации загрузчика Codex не выполнялся. [GitHub о README](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes) и [CONTRIBUTING](https://docs.github.com/en/communities/setting-up-your-project-for-healthy-contributions/setting-guidelines-for-repository-contributors) использованы для разделения первого знакомства, запуска и правил участия.
