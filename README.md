
# Мультиагентная система управления складом

Веб-приложение для координации складских задач. Целевой сценарий — физический склад, где работают сотрудники на погрузчиках и другая техника: система распределяет задачи, показывает их состояние и фиксирует подтверждённое выполнение. Симуляция нужна для демонстрации и разработки логики управления.

**Важно:** текущая версия — демонстрационный прототип. Она показывает виртуальный склад; добавлен планшетный экран водителя, который отображает состояние выбранного симулируемого погрузчика, его задачу и маршрут в реальном времени. Физическая техника, рабочий режим сотрудников и интеграция с WMS, сканерами или системой позиционирования пока не подключены. Физическое перемещение товара в будущей рабочей версии должно считаться выполненным только после подтверждения сотрудника или доверенной внешней системы.

## Текущий прогресс

В приложении есть карта демонстрационного склада, два виртуальных исполнителя, демонстрационные заказы, каталог складских позиций, панель диспетчера и отдельный планшетный экран водителя. На планшете видны этапы задания, положение погрузчика, собственный маршрут, груз и клетки до цели; водитель принимает задание и подтверждает забор/доставку; можно остановить/продолжить виртуальное движение и сообщить о заторе. При перепланировании карта водителя получает обновлённый путь через WebSocket. Позиции товара имеют размер и статус: свободна, зарезервирована, забрана или доставлена. Детерминированный менеджер выбирает назначение по приоритету заказа, расстоянию и вместимости; агент маршрута строит кратчайший путь, агент зоны учитывает перекрытые проходы. Это симуляционный режим без LLM.

Целевое развитие: задания для людей и техники, подтверждение принятия/начала/завершения задания, фиксация фактического места товара, затем — LLM-планирование и адаптеры к доступным системам склада. LLM будет предлагать планы, а backend проверять ограничения и хранить подтверждённые факты.

## Как показать рабочий сценарий

1. В центре управления нажмите «Начать симуляцию». Товары резервируются, задания ждут принятия водителями.
2. В строке погрузчика нажмите «Планшет ↗»: он откроется в отдельной вкладке, а диспетчерская панель останется доступной. На планшете можно выбрать R-01 или R-02.
3. Проверьте товар и адреса, нажмите «Принять задание». Начнётся моделирование движения. На карте выделен только маршрут выбранного погрузчика; другая техника показана серым.
4. По прибытии нажмите «Подтверждаю: товар забран». До подтверждения погрузчик остаётся у места забора.
5. Кнопка «Проход передо мной перекрыт» закрывает следующую клетку собственного маршрута. Система рассчитывает обход либо ждёт свободного пути. Диспетчер может нажать «Открыть проходы».
6. В точке доставки нажмите «Подтверждаю: товар доставлен». Заказ завершится, учётная позиция товара изменится, погрузчик освободит отгрузку и вернётся на стоянку.

Подтверждения проходят серверную проверку: нельзя забрать товар из другой точки, завершить чужое/устаревшее задание или повторно подтвердить доставку. При потере связи команды блокируются и экран показывает, что данные могут быть устаревшими. Пауза симуляции останавливает движение, но позволяет подтвердить уже выполненную операцию.

**Границы прототипа:** всё состояние хранится в памяти и сбрасывается при перезапуске backend. Планшет — демонстрационный интерфейс без авторизации, сканера и реального позиционирования. Кнопка сообщения о препятствии моделирует закрытие клетки. Размеры грузов условные; физические габариты погрузчика, торможение и реальные нормативы движения ещё не моделируются. Для этой демонстрации достаточно открыть две вкладки на одном компьютере; подключение физических устройств требует отдельной настройки сети и доступа.

## Проверки

```bash
python3 -m unittest discover -s tests -v
cd frontend
npm run build
```

Проверки покрывают обязательные подтверждения, отказ от недопустимых действий, затор на собственном маршруте, восстановление пути и завершение всей смены без совпадения позиций техники.

## Запуск backend

Нужен Python 3.11 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
uvicorn backend.main:app --reload
```

После запуска:

- API: <http://127.0.0.1:8000>
- интерактивная документация API: <http://127.0.0.1:8000/docs>
- начальное состояние склада: <http://127.0.0.1:8000/api/state>
- WebSocket обновлений: `ws://127.0.0.1:8000/ws/state`

Основные команды API: `POST /api/simulation/start`, `POST /api/simulation/pause`, `POST /api/simulation/reset`, `POST /api/simulation/congestion`, `POST /api/robots/{robot_id}/stop` и `POST /api/robots/{robot_id}/resume`.

## Запуск веб-интерфейса

В отдельном терминале:

```bash
cd frontend
npm install
npm run dev
```

Откройте <http://localhost:5173>. Backend и frontend должны быть запущены одновременно. Интерфейс подключается к backend на `http://127.0.0.1:8000`.

Подробный контракт компонентов см. в [architecture.md](architecture.md).
