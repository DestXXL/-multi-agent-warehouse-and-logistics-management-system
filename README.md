# Мультиагентная система управления складом и логистикой

Учебный веб-прототип клеточного склада. Диспетчер запускает смену и наблюдает за заказами; на планшетном экране водитель принимает задание и подтверждает забор и доставку виртуального товара. Назначение, построение маршрута и учёт перекрытий выделены в три детерминированные роли, которые синхронно вызывает одна симуляция. Самостоятельных процессов агентов, LLM и управления физической техникой нет.

Реализованы приоритетная очередь, резервирование, движение по маршруту BFS, ожидание и перестроение при перекрытии, общий снимок состояния через WebSocket. Конструктор проверяет геометрию склада, импортирует и экспортирует JSON. Начальная карта – 12 × 8, два погрузчика и три заказа; пользовательский макет меняет размеры и число погрузчиков. Состояние хранится в памяти одного процесса. Подробный механизм и контракты – в [архитектуре](architecture.md), готовность и ограничения – в [статусе](docs/project-status.md).

## Быстрый запуск

Нужны Python 3.11+, Node.js и npm. В Windows PowerShell из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.txt
npm --prefix frontend ci
```

Запустите сервер и интерфейс в отдельных терминалах из корня:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

```powershell
npm --prefix frontend run dev
```

Откройте [диспетчерскую](http://127.0.0.1:5173/?view=control). Для Linux/macOS, проверки адресов и диагностики используйте [DEVELOPMENT.md](DEVELOPMENT.md).

## Демонстрация

1. После свежего запуска нажмите «Начать симуляцию». ORD-001 назначается R-01, ORD-002 – R-02, ORD-003 остаётся в очереди до освобождения ресурса.
2. Откройте «Планшет ↗» у R-01, примите задание и дождитесь прибытия к товару. Подтвердите забор – прибытие само по себе товар не забирает.
3. При доступной кнопке сообщите «Проход передо мной перекрыт» и наблюдайте обход или ожидание. Диспетчер может открыть проходы.
4. По прибытии к отгрузке подтвердите доставку. Заказ станет `completed`; погрузчик ещё возвращается на стоянку. Следующий заказ назначается после перехода ресурса в `idle`.

Для показа нового склада и создания демозаказа используйте [сценарий конструктора](DEMO-LAYOUT.md). Сброс сохраняет применённую геометрию, а перезапуск backend возвращает встроенную карту.
