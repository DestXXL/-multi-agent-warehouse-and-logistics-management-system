# Инструкции для работы с проектом

Перед работой прочитайте этот файл, `README.md`, `architecture.md` и документацию, относящуюся к текущей задаче. Контекст конкретного компонента и роли читайте, если задача затрагивает эту область. Проверяйте актуальность документов по коду и тестам.

## Проект и стек

Курсовой прототип управления складом и логистикой: виртуальные погрузчики выполняют заказы с подтверждениями водителя. Backend – Python 3.11+, FastAPI, WebSocket, состояние в памяти. Frontend – React 19, TypeScript, Vite. Реальной техники, WMS, авторизации и LLM сейчас нет.

## Архитектурные правила

* `backend/models.py` – данные склада; `backend/simulation.py` – единственный владелец изменяемого состояния, резервов, фаз и событий; `backend/agents.py` – детерминированный выбор исполнителя, BFS и блокировки; `backend/main.py` – HTTP и WebSocket.
* `frontend/src/App.tsx` – диспетчерская и планшет водителя; `tests/test_workflow.py` – проверки цикла. Состав компонентов зависит от ветки, проверяйте дерево исходников перед работой.
* Планировщики предлагают назначения и маршруты. Состояние и подтверждённые факты меняет backend после проверки. Внешний планировщик не должен управлять складом напрямую. Проверяйте, использует ли текущая версия LLM, прежде чем описывать её как реализованную.
* Сохраняйте существующий API, поля `robots`, `Robot`, `/api/robots/...` и поведение водителя до согласованного изменения контракта. Не считайте план или виртуальное прибытие подтверждением забора либо доставки.
* Инварианты: одна активная задача у погрузчика; товар резервируется за одним заказом; вместимость учитывается; техника не входит в препятствие, перекрытую или занятую клетку; подтверждения требуют правильного заказа, фазы и позиции. Проверяйте сохранение этих свойств при изменениях.

## Совместная работа и Git

Согласовывайте изменения общих контрактов с владельцами затронутых компонентов и соблюдайте ветвление, принятое для текущей задачи. Перед изменениями проверяйте текущую ветку, remote и `git status`. Сохраняйте незакоммиченные изменения и не удаляйте чужую работу. Для необратимых Git операций и публикации изменений требуется явное задание. Не сохраняйте секреты в репозитории.

## Проверка

Из корня: `python -m pip install -r backend/requirements.txt`, `python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000`, `python -m unittest discover -s tests -v`. Для интерфейса: `cd frontend`, `npm ci`, `npm run dev`, `npm run build`. После интеграции конструктора установите также `backend/requirements-dev.txt` для его тестов. На Windows команда `py -3` может быть недоступна – используйте установленный `python` или интерпретатор виртуального окружения.
