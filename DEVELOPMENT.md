# Окружение, запуск и проверка

Все команды выполняются из корня репозитория, если не сказано иначе. Инструкция рассчитана на локальную демонстрацию одного склада в одном процессе.

## Требования

| Компонент | Требование |
| --- | --- |
| Python | 3.11+; код использует `datetime.UTC` |
| Node.js и npm | Проверены Node.js 24.15.0 и npm 11.12.1; отдельного `engines` у проекта нет |
| Браузер | HTTP, WebSocket и современный JavaScript |
| Порты | 8000 для backend, 5173 для frontend |

В lock-файле Vite 6.4.4 объявляет Node `^18.0.0 || ^20.0.0 || >=22.0.0`. Это диапазон зависимости, а не свидетельство проверки проекта на всех этих версиях.

Python-зависимости задаются диапазонами: `fastapi>=0.115,<1.0`, `uvicorn[standard]>=0.30,<1.0`; для тестов добавлен `httpx>=0.28,<1`. Pydantic поступает транзитивно через FastAPI. Python lock-файла нет, поэтому новая установка может дать другие версии. Frontend фиксируется `frontend/package-lock.json`; используйте `npm ci`.

## Windows PowerShell

Один раз создайте окружение и установите зависимости:

```powershell
python --version
node --version
npm --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.txt
npm --prefix frontend ci
```

Прямой вызов интерпретатора окружения не требует активации PowerShell-скрипта. Если `python` отсутствует, установите Python 3.11+; `py -3` можно использовать только при наличии Windows Python Launcher.

Первый терминал:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Второй терминал:

```powershell
npm --prefix frontend run dev
```

Откройте [интерфейс](http://127.0.0.1:5173). Завершайте каждый процесс через Ctrl+C в его терминале. Для обычной демонстрации режим autoreload не нужен: перезапуск backend сбрасывает состояние.

## Linux и macOS

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-dev.txt
npm --prefix frontend ci
.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

В отдельном терминале из корня:

```bash
npm --prefix frontend run dev
```

Эти команды используют стандартное расположение venv; в рамках аудита запуск на Linux/macOS не выполнялся.

## Проверка запуска и адреса

`GET http://127.0.0.1:8000/api/state` должен вернуть JSON. Корневой путь backend `/` не обслуживает frontend и может вернуть 404. Интерактивное описание HTTP API находится в [Swagger UI](http://127.0.0.1:8000/docs).

Экран выбирается параметрами адреса:

| Экран | Адрес |
| --- | --- |
| Диспетчерская | [view=control](http://127.0.0.1:5173/?view=control) |
| Планшет R-01 | [view=driver](http://127.0.0.1:5173/?view=driver&vehicle=R-01) |
| Конструктор | [view=layout](http://127.0.0.1:5173/?view=layout) |

Для воспроизведения исходной смены используйте [сценарий README](README.md); для пользовательского склада – [DEMO-LAYOUT.md](DEMO-LAYOUT.md).

API и WebSocket привязаны во frontend к `window.location.hostname:8000`. В Vite нет proxy. Если порт 5173 занят, Vite может выбрать другой, но CORS backend этого origin не разрешает. Не считайте HTTP 200 от Vite доказательством связи с API. Найдите владельца занятого порта и согласуйте освобождение, не завершайте чужой процесс автоматически.

Текущий `npm run dev` слушает `0.0.0.0`, а приведённая команда backend – только loopback. Подключение физического планшета требует отдельной сетевой настройки, CORS и мер доступа; текущая инструкция показывает две вкладки одного компьютера. HTTPS-публикация также требует изменений, поскольку frontend формирует `http://` и `ws://`.

## Тесты и сборка

После установки зависимостей, Windows:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
npm --prefix frontend run build
git diff --check
```

Linux/macOS: первая команда – `.venv/bin/python -m unittest discover -s tests -v`.

| Набор | Что проверяет | Что не доказывает |
| --- | --- | --- |
| `tests/test_workflow.py`, 5 тестов | Подтверждения, устаревшее задание, остановку, перекрытие, восстановление пути и завершение смены без совпадения позиций | Разрешение всех взаимных блокировок и безопасность физической техники |
| `tests/test_layout.py`, 10 тестов | JSON/сброс, стеллажи и адреса, сохранение индивидуальных параметров, распределение количества по адресам, резервы, отмену, отказ применения без мутации, несвязную карту и доставку после применения макета | Все допустимые геометрии, браузер и сетевой WebSocket |
| `tests/test_storage_capacity.py`, 15 тестов | Размеры в мм, автоматические профили, двухмерное размещение без пересечений, поворот, запрет неподходящей формы, заполнение, освобождение, резервы двух роботов, снимок/восстановление и безопасное изменение размеров | Физическая укладка на реальном складе и поддержка штабелирования |
| `npm run build` | Проверку TypeScript и сборку Vite | Корректность пользовательского сценария в браузере |

Тест `test_existing_agents_run_custom_layout` повторно применяет геометрию исходного склада; это интеграционная проверка преобразования макета, а не перебор произвольных карт. Тест с именем `test_disconnected_and_inaccessible` проверяет несвязную карту, но отдельного случая изолированного стеллажа в нём нет.

Команд `npm test`, `npm run lint`, конфигурации CI и серверного обслуживания `frontend/dist/` в репозитории нет. Сборка создаёт статические файлы, но сама не разворачивает приложение.

### Зафиксированный проверочный прогон

15 октября 2026 года на `cf9949b` в Windows 10 тестов прошли через установленное `backend/requirements-dev.txt`, а `npm run build` завершился успешно. Использовались Python 3.11.9, Node.js 24.15.0, npm 11.12.1; установились FastAPI 0.143.2, Uvicorn 0.54.0, Pydantic 2.14.1, Starlette 1.8.0, httpx 0.28.1, React 19.3.1, TypeScript 5.7.3 и Vite 6.4.4. Это наблюдение об окружении опыта, а не закреплённый набор версий. Код приложения между `cf9949b` и `f503f86` не менялся; при новой установке результаты нужно перепроверять.

Дополнительно в отдельном серверном процессе проверялись JSON 4 × 4 из [DEMO-LAYOUT.md](DEMO-LAYOUT.md), отказ ошибочного макета без изменения состояния, ответы 404/409/422, начальный и обновлённый снимки WebSocket. HTTP-сценарий создания заказа, принятия, забора, доставки и возврата занял 12 тактов в одном опыте. В браузере были просмотрены диспетчерская, конструктор и названия действий через frontend соседней рабочей копии с теми же исходниками; полный цикл кнопок не проходили. Для повтора используйте новый процесс backend, не сбрасывая чужую демонстрацию; последовательность действий интерфейса описана в [README](README.md). Это не браузерный сквозной тест и не измерение производительности. Отдельные опыты S1 и S3 и их ограничения записаны в [реестре](docs/project-status.md).

## Типичные проблемы

| Наблюдение | Причина и действие |
| --- | --- |
| `ModuleNotFoundError: fastapi` или `httpx` | Проверьте интерпретатор; установите `requirements-dev.txt` именно в используемое окружение |
| «Backend пока не запущен» | Проверьте `/api/state`, порт 8000 и имя хоста страницы |
| Видна карта, но команды не работают | Проверьте WebSocket `/ws/state`, origin, ошибки сети; наличие HTML не доказывает подключение |
| Погрузчик стоит | Проверьте фазу, принятие/подтверждение, паузу, индивидуальную остановку и свободный путь |
| Макет не применяется, HTTP 409 | Паузы недостаточно после начала смены; явный сброс удалит её прогресс |
| После применения нет заказов | Это предусмотрено; добавьте демозаказ кнопкой конструктора |
| После reset осталась изменённая карта | Reset сохраняет пользовательскую геометрию; встроенный склад возвращает перезапуск backend |

Для сообщения о дефекте укажите коммит, версии окружения, исходный/экспортированный макет, шаги, ответ API и ожидаемый результат. Журнал в памяти ограничен; для воспроизводимого опыта фиксируйте снимки до и после команд. Не включайте секреты или посторонние данные.
